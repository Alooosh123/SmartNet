# تجهيز وتشغيل وكلاء SmartNet على n8n المحلي – Windows

## ما يحتويه المستودع الآن

يحتوي على 13 Workflow مستقلاً، و13 System Prompt عربية، وسجل الوكلاء وسياسة الموافقات. تمت إضافة عقدة AI Agent 3.1 وعقدة OpenAI Chat Model 1.2 لكل Workflow، وهما متوافقتان مع n8n 2.49.5. النموذج مستشار للقراءة والتحليل فقط ولا يملك أدوات تنفيذ.

## أول مرة: استيراد الوكلاء

إذا لم تستورد الوكلاء من قبل، استخدم:

~~~powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\automation\n8n\scripts\Import-SmartNetAgents.ps1
~~~

يقوم المستورد بإنشاء نسخة احتياطية واستيراد الـ13 Workflow غير منشورة. لا ينشئ اعتماد OpenAI أو Header Auth.

## إذا كانت الوكلاء مستوردة مسبقاً (الحالة الحالية)

بما أنك استوردت الوكلاء سابقاً، لا تشغّل المستورد مرة أخرى. بعد دمج PR التحديث في main:

~~~powershell
cd D:\SmartNet
git pull origin main
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\automation\n8n\scripts\Update-And-Test-SmartNetAgents.ps1
~~~

يقوم Updater بالتالي:
1. يتأكد أن إصدار n8n يساوي 2.49.5.
2. يصدر نسخة احتياطية من Workflows المحلية قبل أي تغيير.
3. يتأكد أن عدد Workflows المحلية يساوي 31 وفق آخر تدقيق، لمنع تعديل قاعدة n8n مختلفة عن القاعدة التي جرى تدقيقها.
4. يقرأ أسماء ومعرّفات الاعتمادات المحلية من تصدير Credentials المشفر افتراضياً؛ لا يستخدم خيار decrypted ولا يطبع أي قيمة سرية.
5. يربط عقد OpenAI باعتماد openAiApi المحلي.
6. يطلب اختيار اعتماد Webhook من نوع httpHeaderAuth عند وجود أكثر من اعتماد.
7. يحدّث الـ13 Workflow الموجودة باستخدام معرّفاتها الحالية، لا ينشئ نسخاً مكررة.
8. يعيد تصدير Workflows للتحقق من اتصالات النموذج والمصادقة وبقاء كل Workflow غير منشورة.
9. ينفذ اختبار Manual Trigger محلياً لكل وكيل، ويسجل نتيجة كل اختبار.

يلزم وجود:
- اعتماد OpenAI API من النوع openAiApi محفوظ في n8n.
- اعتماد Header Auth من النوع httpHeaderAuth محفوظ في n8n.
- تشغيل CLI تحت حساب Windows وبيئة N8N نفسها التي تحتوي Workflows الحالية.

إذا لم يجد اعتماداً أو Workflow، أو اختلف إصدار n8n أو عدد Workflows عن التدقيق الأخير، يتوقف قبل التحديث. إذا حدث فشل في مرحلة الاستيراد أو التحقق يحاول استرجاع النسخ الاحتياطية.

## ما تثبته الاختبارات

اختبارات Manual Trigger تتحقق من أن n8n يستطيع تشغيل عقدة النموذج محلياً وإرجاع المخرجات. الوكيلان 06 و11 يستخدمان fixture محلياً لاختبار سلسلة النموذج فقط، ولا يثبت ذلك أن FastAPI يعمل. الوكيلان 01 و02 يطلبان شجرة GitHub العامة. الاختبارات الأخرى تستخدم مدخلات حراسة آمنة ولا تغير حالة النظام.

هذه الاختبارات لا تثبت اتصال MikroTik الحقيقي أو مزود الدفع أو استعادة قاعدة الإنتاج أو جاهزية الخادم العام.

## النشر الفعلي لـ Webhooks

يترك السكربت جميع Workflows غير منشورة افتراضياً. لا تستخدم خيار النشر قبل التأكد من:
- وجود HTTPS وشهادة TLS صالحة.
- سلامة reverse proxy وWEBHOOK_URL والجدار الناري.
- أن كل مستهلك/تطبيق سيستدعي webhook يستخدم اسم الرأس والقيمة المطابقين لاعتماد Header Auth الذي تم اختياره.
- أن الوصول مقيد بشبكة خاصة/VPN أو ضوابط مناسبة.

بعد ذلك فقط، وفي نافذة صيانة مناسبة، يمكن تهيئة متغير البيئة التالي وإعادة تشغيل السكربت بخيار النشر:

~~~powershell
$env:SMARTNET_ALLOW_WEBHOOK_PUBLISH = "YES"
.\automation\n8n\scripts\Update-And-Test-SmartNetAgents.ps1 -PublishAfterSmokeTests
~~~

يلزم أيضاً أن تكون WEBHOOK_URL تبدأ بـ https:// أو N8N_PROTOCOL=https وأن تنجح اختبارات الوكلاء الـ13. هذا الحارس لا يغني عن فحص TLS والـreverse proxy والتأكد من تكامل التطبيق المستهلك. لا تنشر Webhooks لمجرد ظهورها في واجهة n8n.

## الصلاحيات

- لا توجد AI Tools موصولة إلى وكلاء الذكاء الاصطناعي.
- لا يملك النموذج صلاحية MikroTik أو قاعدة البيانات أو الدفع أو دفتر الأستاذ أو النشر.
- وكلاء 08 و09 و10 يرسلون سياقاً مختصراً بعد إزالة المراجع والمبالغ والهدف/السبب الحساس.
- النتيجة الحتمية تبقى المرجع التشغيلي؛ نص النموذج يظهر كاستشارة في ai_advisory.
- طلب موافقة بشرية لا ينفذ العملية. التنفيذ يحتاج Backend يتحقق من الموافقة الدائمة ويستهلكها مرة واحدة.
- الوكيل 00 يحدد المسار المقترح ولا يستدعي وكلاء آخرين تلقائياً.
