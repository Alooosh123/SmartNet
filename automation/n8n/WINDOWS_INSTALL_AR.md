# تجهيز وكلاء SmartNet على n8n المحلي – Windows

## ما الذي يجهزه هذا الدليل؟

المستودع يحتوي على 13 Workflow و13 System Prompt عربية وسجل للوكلاء. ملفات Workflow الحالية هي حواجز منطقية محددة (Webhook/Code/HTTP Request/Response)، وليست 13 وكيلاً ذكياً مستقلاً متصلاً بنموذج محادثة. لا توجد حالياً عقد AI Agent أو Chat Model موصولة داخل ملفات JSON، وحالة LLM مسجلة عمداً على أنها prompt_ready_not_connected.

## 1. المتطلبات

- n8n مثبت ويعمل على جهاز Windows.
- نسخة من مستودع SmartNet على الجهاز.
- صلاحية PowerShell على نفس حساب Windows الذي يشغّل n8n أو يستخدم قاعدة بياناته.
- لا تضع API keys أو كلمات مرور في Git أو ملفات JSON أو هذه المحادثة.

تحقق من إصدار n8n:

    n8n --version

## 2. استيراد جميع الوكلاء

من مجلد المشروع:

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
    .\automation\n8n\scripts\Import-SmartNetAgents.ps1

يقوم السكربت بما يلي:
1. يتحقق من وجود ملفات الوكلاء الـ13 وصحة JSON وأن كل ملف يحمل active=false.
2. ينشئ نسخة احتياطية من Workflows الموجودة في Documents\SmartNet-n8n-backups\<timestamp>.
3. يوقف الاستيراد إذا وجد Workflow باسم SmartNet موجوداً مسبقاً، لتجنب إنشاء نسخ مكررة.
4. يستورد الملفات إلى قاعدة n8n الخاصة بالحساب/البيئة التي شغّل منها الأمر، ويتركها غير منشورة/غير مفعّلة.

**مهم:** لا تشغّل السكربت على حساب Windows مختلف عن حساب خدمة n8n إلا بعد ضبط نفس N8N_USER_FOLDER ومفاتيح البيئة المعتمدة للخدمة. واجهة n8n وخدمة CLI قد تصلان إلى قاعدتي بيانات مختلفتين إذا اختلف الحساب أو البيئة.

## 3. إعداد المصادقة قبل النشر

كل Workflow يبدأ بعقدة Webhook. ملفات JSON الحالية لا تحتوي على إعداد مصادقة Webhook أو مرجع Credential. لذلك:

- اترك جميع Workflows غير مفعّلة.
- أنشئ Credential للمصادقة داخل n8n، ولا تضع السر في JSON.
- أضف إعداد المصادقة إلى كل Webhook Trigger، واختبر طلباً صحيحاً وآخر بدون اعتماد وآخر باعتماد خاطئ.
- لا تنشر أي Webhook على الإنترنت قبل TLS ومصادقة واختبار حدود الوصول.

## 4. ترتيب الاختبار الأولي

بعد إضافة المصادقة على Webhook، ابدأ بمسارات القراءة/الفحص التالية على بيئة محلية:

| الوكيل | النطاق | ملاحظة |
|---|---|---|
| 01 | قراءة شجرة مستودع GitHub | جرد ملفات فقط |
| 02 | فحص أسماء ومسارات الملفات | ليس فحص أسرار للمحتوى |
| 06 | طلب GET /api/health | لا يثبت سلامة قاعدة البيانات أو الراوتر |
| 11 | اختبار صحة بسيط | لا ينفذ اختبارات تغيّر البيانات |

بعدها اختبر الوكلاء 03 و04 و05 و07 و08 و09 و10 و12 بمدخلات تجريبية غير حقيقية. هذه المسارات تُراجع أو تتحقق أو تقترح؛ ولا تمنحها صلاحيات كتابة.

## 5. ربط الذكاء الاصطناعي

لتحويل التعليمات إلى وكلاء LLM فعليين:
1. أنشئ Credential لمزود النموذج من واجهة n8n.
2. أضف عقدة Chat Model المدعومة في إصدارك المحلي، ثم عقدة AI Agent لكل Workflow يحتاج الاستدلال.
3. ضع ملف System Prompt الموافق من automation/n8n/prompts/ في System Message.
4. مرر مدخلات المستخدم منفصلة عن System Message.
5. أضف تحققاً صارماً من JSON ومخطط المخرجات. عند فشل التحقق، أوقف المسار.
6. ابدأ بأدوات قراءة فقط. لا تربط النموذج مباشرةً بقاعدة الإنتاج أو RouterOS أو بوابة الدفع.

لا يمكن تحديد مخطط عقدة AI Agent بدقة قبل معرفة إصدار n8n والعقد المتاحة لديك. لا ترسل مفاتيح API في المحادثة؛ أنشئ بيانات الاعتماد محلياً.

## 6. العمليات المحظورة على الوكلاء

يجب أن تبقى هذه العمليات خلف Backend وصلاحيات وموافقة بشرية دائمة وسجل تدقيق:
- إعادة تشغيل الراوتر أو فصل مستخدم أو تغيير Firewall.
- اعتماد دفع أو تفعيل اشتراك أو تعديل رصيد.
- استعادة قاعدة بيانات أو تنفيذ ترحيل إنتاجي.
- نشر إصدار أو تعديل DNS/الخادم.

صورة الإيصال ليست إثبات تسوية. المطابقة المالية لا تكتب دفتر الأستاذ. الوكيل 10 ينشئ/يعرض طلب موافقة ولا ينفذ الإجراء.

## حالة القبول

| البند | الحالة |
|---|---|
| 13 Workflow في GitHub | جاهزة |
| 13 System Prompt عربية | جاهزة |
| استيراد محلي عبر السكربت | يحتاج تشغيله على جهازك |
| Webhook Authentication | يحتاج إعداد Credential محلياً |
| عقد AI Agent / Chat Model | غير موصولة حتى الآن |
| نشر/تفعيل Workflows | مؤجل عمداً حتى إكمال المصادقة والاختبار |
| ربط MikroTik حقيقي | يحتاج راوتر اختبار معزولاً |
| ربط مزود الدفع الحقيقي | يحتاج API رسمي/اعتمادات مزود واختبارات تسوية |

لا يعتبر نجاح استيراد ملفات JSON اختباراً لتشغيل n8n أو اتصال GitHub أو الراوتر أو المدفوعات.
