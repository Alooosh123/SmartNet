# ربط وكلاء SmartNet مع OpenAI في n8n 2.49.5

## الحالة في المستودع

تم تحديث ملفات الوكلاء الـ13 لتحتوي على:
- عقدة AI Agent بإصدار 3.1.
- عقدة OpenAI Chat Model بإصدار 1.2، والنموذج الافتراضي gpt-5-mini.
- وصلة ai_languageModel بين النموذج والوكيل.
- System Prompt عربي مستقل لكل وكيل.
- مرحلة لتقليل البيانات قبل إرسالها للنموذج.
- مرحلة نهائية تضيف رأي النموذج دون استبدال نتيجة التحقق الحتمية.
- Webhook Trigger مضبوط على Header Auth.
- Manual Trigger لاختبار الوكيل محلياً دون نشر Webhook.

تمت مطابقة أنواع العقد وإصداراتها مع مصدر n8n tag n8n@2.49.5. لا توجد معرّفات Credentials أو مفاتيح سرية في ملفات Git.

## تطبيق التحديث على قاعدة n8n المحلية

بعد دمج التحديث في main، نفّذ من PowerShell:

~~~powershell
cd D:\SmartNet
git pull origin main
Set-ExecutionPolicy -Scope Process Bypass -Force
.\automation\n8n\scripts\Update-And-Test-SmartNetAgents.ps1
~~~

يقوم السكربت بإنشاء نسخة احتياطية من جميع Workflows المحلية، والتحقق من إصدار n8n، وقراءة أسماء ومعرّفات Credentials المحلية من تصدير n8n المشفر افتراضياً دون فك قيمها السرية أو عرضها، ثم ربط OpenAI وHeader Auth محلياً. بعد ذلك يحدّث الـ13 Workflow الموجودة بمعرّفاتها الحالية، ويعيد تصديرها للتحقق من العقد والاتصالات، وينفذ اختباراً يدوياً لكل وكيل.

إذا لم يجد اعتماد OpenAI أو Header Auth أو إحدى Workflows المحلية، يتوقف ولا يبدأ التحديث. إذا فشل التحديث في منتصف الاستيراد يحاول استرجاع النسخ الاحتياطية التي أنشأها.

## نشر Webhooks

لا تنشر المسارات لمجرد نجاح الاستيراد. تحقق من HTTPS أو شبكة VPN خاصة، وشهادة TLS، وreverse proxy، وقواعد الجدار الناري، واعتماد Header Auth. الوضع الافتراضي يبقي Workflows غير منشورة.

يوجد خيار نشر اختياري:

~~~powershell
.\automation\n8n\scripts\Update-And-Test-SmartNetAgents.ps1 -PublishAfterSmokeTests
~~~

لا يحاول النشر إلا بعد نجاح اختبارات الوكلاء الـ13 ووجود مؤشر HTTPS في متغيرات البيئة. هذا المؤشر لا يغني عن فحص TLS والوصول الفعلي. عند فشل النشر يحاول إلغاء نشر ما نشره خلال المحاولة.

## حدود الصلاحيات

- النموذج مستشار فقط؛ لا توجد AI Tools موصولة.
- لا يملك الوكيل صلاحية RouterOS أو قاعدة البيانات أو بوابة الدفع أو دفتر الأستاذ أو نشر الإنتاج.
- وكلاء 08 و09 و10 يرسلون حقول حالة مختصرة فقط، ولا يرسلون مراجع التحويل أو مبالغ الدفع أو الهدف وسبب طلب الموافقة إلى النموذج.
- قرار Code nodes الحتمي هو القرار التشغيلي. مخرجات OpenAI تضاف في ai_advisory ولا تعتمد دفعاً ولا تفعّل اشتراكاً ولا تنفذ تغييراً شبكياً.
- الوكيل 00 يحدد الوكيل والمسار المطلوب ولا يستدعيه تلقائياً.
- اختبار التشغيل اليدوي لا يثبت تكامل MikroTik الحقيقي أو موفر الدفع أو سلامة Backend وقاعدة البيانات.
