# SmartNet — وكلاء الذكاء الاصطناعي في n8n

تحتوي الحزمة على 13 Workflow مستقلاً، ولكل وكيل System Prompt عربي وعقدة AI Agent 3.1 متصلة بعقدة OpenAI Chat Model 1.2. النموذج المحدد افتراضياً هو `gpt-6-luna` عبر Chat Completions. ملفات Git لا تحتوي على معرّفات اعتماد أو مفاتيح سرية.

## وضع التشغيل

- جميع Workflows في ملفات المستودع غير منشورة افتراضياً.
- جميع الوكلاء يتبعون نمط `deterministic_guardrail_with_llm_advisory`: Code node ينفذ التحقق الحتمي أولاً، ثم يحلل النموذج سياقاً مختصراً، وتضاف النتيجة كـ `ai_advisory` دون أن تستبدل قرار التحقق.
- لا توجد AI Tools موصولة. النموذج لا يملك صلاحية تنفيذ أوامر أو اتصالاً مباشراً بقاعدة البيانات أو RouterOS أو الدفع أو دفتر الأستاذ.
- مصادقة Header Auth مطلوبة لكل Webhook Trigger. تُحقن معرّفات الاعتماد محلياً بعد إنشاء Credentials في n8n.

## تشغيل النسخة المحلية الموجودة لديك

بما أنك استوردت الوكلاء الـ13 سابقاً إلى قاعدة n8n المحلية، لا تستخدم Importer مرة ثانية. اتبع [دليل Windows](./WINDOWS_INSTALL_AR.md) وشغّل:

```powershell
cd D:\SmartNet
git pull origin main
Set-ExecutionPolicy -Scope Process Bypass -Force
.\automation\n8n\scripts\Update-And-Test-SmartNetAgents.ps1
```

يقوم المحدث بإنشاء نسخة احتياطية من كل الـ31 Workflow، ويربط اعتماد OpenAI واعتماد Header Auth المخصص، ويحدّث نفس معرّفات الوكلاء الـ13، ثم يجري اختباراً محلياً من خلال Manual Trigger لكل وكيل. يجب إنشاء اعتمادين محليين مسبقاً:
- OpenAI API Credential من النوع `openAiApi`.
- Header Auth Credential بالاسم `SmartNet Agents Header Auth` ورأس `X-SmartNet-Agent-Key` وقيمة عشوائية قوية لا تقل عن 32 حرفاً.

لا ترسل أي مفتاح أو اعتماد في GitHub أو المحادثة.

## جسر FastAPI إلى n8n

أضيفت واجهة إدارية اختيارية ومحمية في Backend:
- `GET /api/v1/automation/agents`
- `POST /api/v1/automation/agents/{agent_id}/invoke`
- `POST /api/v1/automation/dispatch`

المسار الأخير يطلب من الوكيل 00 تصنيف المهمة، ثم يتحقق Backend أن الوكيل والمسار يعادلان القائمة الثابتة قبل استدعاء الوكيل الفرعي. جميع هذه المسارات تتطلب حساب مدير وتخضع لحدود طلبات.

الإعداد الافتراضي `N8N_ENABLED=false`. بعد إعداد الاعتماد نفسه في n8n وBackend، أدخل في ملف `backend/.env`:

```dotenv
N8N_ENABLED=true
N8N_BASE_URL=http://127.0.0.1:5678
N8N_WEBHOOK_AUTH_HEADER=X-SmartNet-Agent-Key
N8N_WEBHOOK_AUTH_VALUE=<same-random-secret-as-n8n-credential>
N8N_TIMEOUT_SECONDS=12
```

قيمة `N8N_WEBHOOK_AUTH_VALUE` يجب أن تطابق قيمة اعتماد Header Auth المحلي تماماً. لا تحفظ السر في Git. وضع الإنتاج يرفض HTTP ويشترط HTTPS.

## المهام المسموحة والمحظورة

المهام المسموحة تشمل تدقيق المستودع والأمن والصلاحيات والنسخ الاحتياطي ومتطلبات MikroTik والصحة والتشخيص واستقبال مدخلات الدفع والمطابقة وطلبات الموافقة وQA وما قبل الإصدار.

المشرف لا يستطيع تمرير إعادة تشغيل الراوتر أو فصل مستخدم أو تغيير Firewall أو اعتماد الدفع أو تفعيل اشتراك أو استعادة قاعدة الإنتاج أو نشر النظام. كما أن Backend يتحقق من المسار المعاد مقابل قائمة السماح؛ لا يثق في أي URL يعيده النموذج.

## تقليل البيانات قبل n8n

- لا ترسل وكلاء 01 و02 و06 و11 بيانات طلب لا يحتاجونها.
- يتلقى الوكيل 07 المقاييس الرقمية المسموح بها فقط، بلا نصوص ملاحظات أو بيانات مشتركين.
- يتلقى الوكيل 08 علامات وجود حقول الدفع، دون المرجع الفعلي أو المبلغ أو العملة أو اسم المحفظة.
- يقارن Backend بيانات التسوية للوكيل 09 ثم يرسل رموز الاختلاف وعلامات الوجود فقط، لا القيم الفعلية.
- يتلقى الوكيل 10 الإجراء وعلامتي وجود الهدف والسبب، دون نص الهدف أو السبب.
- بقية الوكلاء تستخدم قوائم سماح وحقول مراجعة محدودة.
- سجل التدقيق في Backend يحتفظ بمعرّف الطلب والوكيل والحالة فقط؛ ولا يحفظ Body الطلب أو مفاتيح المصادقة.

## نطاق كل وكيل

- 00: يصنف المهمة ويعيد مسار الوكيل المعتمد؛ Backend هو من ينفذ التوجيه الثابت.
- 01: يقرأ شجرة GitHub العامة للفرع main، ولا يراجع محتوى كل مصدر برمجياً.
- 02: فحص مسارات الملفات فقط؛ لا يحل محل Gitleaks أو pip-audit أو Bandit.
- 03: يراجع مصفوفة أدوار وصلاحيات محددة.
- 04: يراجع مؤشرات النسخ والترحيل والاستعادة المقدمة.
- 05: يراجع شروط بيئة MikroTik المعزولة ولا ينفذ RouterOS.
- 06 و11: يفحصان GET /api/health فقط؛ لا يثبتان سلامة قاعدة البيانات أو الراوتر.
- 07: يرتب فرضيات تشخيصية على مقاييس إجمالية مقدمة؛ لا يتصل براوتر حقيقي تلقائياً.
- 08: يتحقق من اكتمال مدخلات الدفع ولا يعتمد حوالة أو يفعّل اشتراكاً.
- 09: يصنف اختلافات المطابقة ولا يكتب في Ledger.
- 10: يعرض متطلبات الموافقة ولا ينفذ الإجراء.
- 11: اختبار صحة آمن فقط؛ لا يشغل اختبارات متغيرة على الإنتاج.
- 12: يراجع أدلة go/no-go ولا ينشر التطبيق.

## حدود القبول الفعلي

نجاح GitHub CI أو اختبار Manual Trigger لا يثبت اتصال MikroTik حقيقي أو مزود دفع حقيقي أو تشغيل خادم الإنتاج. قبول MikroTik يتطلب راوتر اختبار معزولاً وشهادة وحساب قراءة فقط. الدفع يتطلب مزوداً ووثائق API رسمية أو مراجعة يدوية فعلية. راجع [دليل التشغيل](./OPERATIONS.md) و[دليل Windows](./WINDOWS_INSTALL_AR.md).
