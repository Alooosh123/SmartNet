# SmartNet n8n Agent Foundation

حزمة تأسيس فريق مكوّن من 13 Workflow داخل n8n. جميعها غير مفعّلة افتراضياً.

## الاستيراد
1. افتح n8n المحلي ثم Workflows > Import from File.
2. استورد ملفات `automation/n8n/workflows/*.json`.
3. اتركها غير مفعّلة حتى إعداد مصادقة Webhook ومراجعة إعدادات HTTP.
4. ابدأ بالوكيل 01 ثم 02 ثم 06 و11. بقية الوكلاء بوابات تحقق ومراجعة وليست تكاملات تشغيلية كاملة.
5. استدعاء المشرف 00 يعيد مسار الوكيل المطلوب. فعّل الوكيل الفرعي أولاً.

## نطاق التنفيذ الحالي
- 01: فهرسة شجرة GitHub للفرع main فقط.
- 02: فحص أسماء المسارات بحثاً عن ملفات أسرار أو ملفات تشغيل متتبعة؛ لا يفحص محتويات الملفات ولا يغني عن Gitleaks أو pip-audit أو Bandit.
- 06 و11: GET إلى FastAPI `/api/health` فقط؛ لا يثبت اتصال MikroTik أو سلامة قاعدة البيانات.
- بقية الوكلاء تستقبل بيانات وتعيد مراجعة أو توصية؛ لا تعدل قاعدة البيانات ولا تنفذ أوامر RouterOS ولا تؤكد مدفوعات ولا تنشر التطبيق.

## إعدادات محلية
عنوان FastAPI الافتراضي `http://127.0.0.1:8000` وعنوان n8n الافتراضي `http://127.0.0.1:5678`. عدّل الإعدادات داخل العقد قبل التفعيل إن اختلفت. إذا كان n8n داخل حاوية فإن 127.0.0.1 يشير إلى الحاوية نفسها.

**تنبيه:** لا تضف أسرار GitHub أو JWT أو MikroTik أو المحافظ إلى ملفات المستودع. أنشئ Credentials داخل n8n، واحمِ Webhooks قبل التفعيل. لم يتم الوصول إلى n8n على جهازك أو تشغيل هذه التدفقات عليه من هذه الجلسة.

## ملاحظات من فحص main
- إعداد قاعدة البيانات الافتراضي SQLite عبر SQLAlchemy async.
- توجد قيم افتراضية حساسة في `backend/config/settings.py`.
- `backend/services/subscription_agent.py` يعتبر وجود صورة إيصال سبباً لتعيين paid وتفعيل الاشتراك؛ يجب إيقاف هذا المسار قبل المدفوعات الحقيقية.
- `backend/services/mikrotik_api.py` قد يعيد بيانات Demo عند فشل الاتصال الحقيقي.
- شجرة main تتضمن ملفات pyc وقاعدة بيانات وملفات PDF وuploads، وتحتاج إلى مراجعة الاستبعاد.
- ملفات README تصف frontend وبوت Telegram غير ظاهرتين في شجرة main التي تمت مراجعتها.
