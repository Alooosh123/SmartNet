# مصفوفة أدوات وصلاحيات وكلاء SmartNet

## قاعدة عامة

تم توصيل كل Workflow بعقدة AI Agent 3.1 وOpenAI Chat Model 1.2. النموذج مستشار مساعد فقط، ولا توجد AI Tools أو صلاحيات تنفيذ موصولة به. نتيجة Code node الحتمية محفوظة في الاستجابة وهي المرجع التشغيلي؛ نص النموذج يظهر منفصلاً داخل ai_advisory.

| الوكيل | نطاق التحليل المسموح للنموذج | المحظور |
|---|---|---|
| 00 Supervisor | تصنيف المهمة واقتراح الوكيل التالي من القائمة المعتمدة | تنفيذ أو استدعاء الوكلاء، عمليات الشبكة والمال والنشر |
| 01 Repository | تفسير جرد شجرة GitHub وملاحظات الملفات | تعديل المستودع أو Push |
| 02 Security | تفسير نتائج أسماء ومسارات الملفات | كشف الأسرار أو الاستغلال أو ادعاء فحص محتوى لم يحدث |
| 03 RBAC | مراجعة مصفوفة الأدوار والصلاحيات المقدمة | منح الصلاحيات أو تعديلها |
| 04 Database | تقييم أدلة النسخ والترحيل والاستعادة المقدمة | حذف أو استعادة أو ترحيل إنتاجي |
| 05 MikroTik Gate | تقييم متطلبات بيئة الاختبار المعزولة | الاتصال بالراوتر أو إصدار أوامر RouterOS |
| 06 Monitoring | تفسير نتيجة GET /api/health | فصل مستخدم أو تعديل واجهة؛ لا يدعي سلامة DB أو الراوتر |
| 07 Diagnosis | ترتيب فرضيات التشخيص ضمن القياسات المقدمة | أوامر RouterOS المتغيرة |
| 08 Payment | تفسير حالة اكتمال الحقول فقط | اعتماد الدفع أو تفعيل الاشتراك أو تغيير الرصيد |
| 09 Reconciliation | تفسير اختلافات الحقول المقدمة بعد إخفاء القيم الحساسة | تعديل دفتر الأستاذ أو سجلات الدفع |
| 10 Approval | شرح متطلبات طلب الموافقة | تنفيذ الإجراء أو اعتبار مجرد طلب الموافقة تفويضاً |
| 11 QA | تفسير نتيجة فحص الصحة المحلي | اختبارات متغيرة على الإنتاج أو ادعاء تشغيل حزمة كاملة |
| 12 Release | تفسير أدلة go/no-go المقدمة | النشر أو DNS أو Restart |

## تقليل البيانات

مرحلة Prepare Minimized AI Context تقلل البيانات قبل إرسالها إلى OpenAI:
- لا ترسل مراجع التحويل أو المبالغ أو العملة الفعلية أو المستفيد إلى الوكيل 08.
- لا ترسل سجلات الدفع التفصيلية أو مراجع المعاملات إلى الوكيل 09.
- لا ترسل الهدف والسبب النصي لطلب الموافقة إلى الوكيل 10.
- لا ترسل جسم استجابة Backend الكامل أو بيانات العملاء إلى وكلاء الصحة.
- لا تمرر نصوصاً حساسة عشوائية إلى System Prompt.

## حواجز Backend الإلزامية

- تحقق من هوية خدمة الأتمتة عبر اعتماد مستقل محدود.
- استخدم قائمة سماح للأفعال والمسارات؛ لا تقبل URL أو أمر نظام يقدمه النموذج.
- عمليات الكتابة تحتاج idempotency key وسجل تدقيق.
- الموافقة البشرية محددة النطاق والمدة والصلاحية وتُستهلك مرة واحدة.
- لا تمنح n8n وصولاً مباشراً إلى بيانات العملاء الحساسة أو مفاتيح الراوتر أو سجلات الرصيد.
- لا تحفظ الإيصالات أو كلمات المرور أو بيانات الدفع في ذاكرة النموذج أو سجلاته.
- أي إضافة مستقبلية لأداة كتابة تتطلب Backend gate منفصلاً واختبارات رفض ومراجعة مستقلة؛ لا توصلها مباشرة إلى AI Agent.
